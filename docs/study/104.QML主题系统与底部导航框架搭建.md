# 104. QML 主题系统与底部导航框架搭建

**日期：** 2026-05-20
**关联开发任务：** 阶段 1 任务 1.4 UI 基础组件
**关联设计文档：** 003.详细设计文档 §1 色彩体系 + 001.概要设计文档 UI 层规范

---

## 一、问题/需求描述

概要设计文档 [001:行43-49] 规定 UI 层必须使用 QML，严禁硬编码色值。详细设计文档 [003:§1] 定义了完整的设计语言：主色 `#64C288`、辅助色 4 种、3 个层级字号的排版系统、3 种圆角规格、3 种动效时长。同时需要底部导航栏承载 4 个核心模块（首页/冰箱/菜谱/我的）。

---

## 二、思路

1. **主题单例**：用 `pragma Singleton` 的 QtObject 集中管理所有视觉常量，C++ 侧通过 `qmlRegisterSingletonType` 注册为 `SmartDiet.Style 1.0`
2. **零硬编码**：任何 QML 组件中的色值、字号、间距、圆角必须引用 `Theme.xxx`
3. **导航框架**：`StackView`（支持子页面推入）+ `TabBar`（底部 4 Tab），`onCurrentIndexChanged` → `replace(null, page, Immediate)`

---

## 三、逻辑推导

### 3.1 为什么选 QML Singleton 而非 C++ 单例

| 方案 | 优点 | 缺点 |
|------|------|------|
| C++ 单例 `qmlRegisterSingletonInstance` | 编译期类型安全 | 需要写 C++ 类 + Q_PROPERTY，QML 端需 `#include` |
| QML `pragma Singleton` | 纯 QML，无需编译 | 需要在 `qmldir` 或 C++ 注册路径 |

选择 QML Singleton + C++ 注册：`qmlRegisterSingletonType(QUrl("qrc:/qml/styles/Theme.qml"), "SmartDiet.Style", 1, 0, "Theme")`，兼顾纯 QML 编写和确定性导入路径。

### 3.2 StackView + TabBar 联动方案

```
TabBar.currentIndex 变化
  ↓
onCurrentIndexChanged
  ↓
navStack.replace(null, pages[currentIndex], StackView.Immediate)
  ↓
StackView 显示目标 Page
```

选择 `replace` 而非 `push`/`pop`：Tab 之间是平级关系，不是父子页面关系，用 replace 保持栈深始终为 1。

### 3.3 页面生命周期

4 个页面作为 ApplicationWindow 的子元素预创建（`HomePage { id: homePage }`），通过 `readonly property var pages: [...]` 数组引用。StackView 接管其 visibility 管理，Tab 切换不销毁页面实例，用户状态（滚动位置、输入框文字）得以保留。

## 四、实施方案

### 4.1 文件清单

```
src/ui/styles/Theme.qml       ← pragma Singleton / 10 色 + 4 字号 + 3 间距 + 3 圆角 + 3 动效
src/ui/qml/main.qml           ← StackView + footer TabBar + 4 页面预实例
src/ui/qml/HomePage.qml       ← 🏠 占位
src/ui/qml/FridgePage.qml     ← 🧊 占位
src/ui/qml/RecipesPage.qml    ← 📖 占位
src/ui/qml/ProfilePage.qml    ← 👤 占位
resources.qrc                 ← 新增 5 个 QML 资源
src/app/main.cpp              ← qmlRegisterSingletonType
```

### 4.2 Theme.qml 关键属性

```qml
pragma Singleton
QtObject {
    readonly property color primary: "#64C288"    // 暖柔青柠绿
    readonly property color danger:  "#E86B6B"    // 豆沙红
    readonly property int   fontSizeTitle: 18
    readonly property int   spacingMedium: 16
    readonly property int   radiusLarge: 16
    readonly property int   durationNormal: 300
}
```

### 4.3 main.qml 结构

```qml
ApplicationWindow {
    StackView { id: navStack; initialItem: homePage }
    footer: TabBar {
        TabButton { text: "🏠\n首页" }
        TabButton { text: "🧊\n冰箱" }
        TabButton { text: "📖\n菜谱" }
        TabButton { text: "👤\n我的" }
    }
    HomePage    { id: homePage }
    FridgePage  { id: fridgePage }
    RecipesPage { id: recipesPage }
    ProfilePage { id: profilePage }
}
```

## 五、可行性分析

| 维度 | 评估 |
|------|------|
| **主题扩展** | 新增颜色/字号只需在 Theme.qml 加一行，所有组件即时生效 |
| **导航扩展** | 每个 Tab 内可独立使用 `navStack.push(detailPage)` 做子页面导航，不影响其他 Tab |
| **性能** | 4 个预创建 Page 的内存开销 ~几 KB，Tab 切换零延迟 |
| **与 C++ 常量对齐** | Theme.qml 的色值与 `constants.h` 的 `ThemeColor` 命名空间一一对应 |

## 七、补充：Material Icons 图标字体集成

### 问题
界面全部使用 emoji 和文字代替图标，不专业，且无法控制图标大小和颜色。

### 方案
引入 Google Material Icons Outlined 字体（339KB，~900 图标），封装 `Icon.qml` 可复用组件。

### 关键踩坑

| 现象 | 根因 | 修复 |
|------|------|------|
| `Type Icon unavailable` | Icon.qml 中 `property color color` 与 Text 基类的 `color` 属性同名冲突，导致 QML 解析失败 | 删除自定义属性，直接使用 Text 内置 `color`，默认值 `Theme.textPrimary` |
| `Property value set multiple times` | 同上 | 同上 |

### 最终 Icon 用法

```qml
Icon { name: "home" }                              // 默认大小+颜色
Icon { name: "delete"; size: 20; color: "red" }     // 自定义
```
