# 201. 注册页面 UI 与独立窗口搭建

**日期：** 2026-05-20
**关联开发任务：** 阶段 2 任务 2.1.1 注册页面 UI
**关联设计文档：** 003.详细设计文档 §2 界面一、009.开发规范文档

---

## 一、问题/需求

003.详细设计文档定义了注册 Step 1 的表单布局：进度 1/2、昵称输入、三列身体数据、性别二选一、饮食目标三选一、底部"下一步"按钮。需要在 QML 中实现这个界面，并作为独立窗口弹出（而非嵌入带 TabBar 的主窗口）。

---

## 二、思路

1. **组件化**：身体数据卡片、性别按钮、目标卡片各自封装为独立 QML 组件，保证复用性和干净的文件结构
2. **信号通信**：子组件通过 `signal clicked(value)` 通知父页面选择变更，避免双向绑定导致的状态混乱
3. **独立窗口**：`RegisterWindow.qml` 作为纯 `ApplicationWindow`，不含 TabBar，测试期间 `main.cpp` 临时指向它
4. **显式布局**：用 `anchors` + `Row` + 显式 `width: parent.width` 做响应式，避免 `ScrollView` 内部的 `parent.width` 解析混乱

---

## 三、逻辑推导

### 3.1 `parent.width` 在 ScrollView 中失控

当组件放在 `ScrollView > Column > Row` 嵌套中，`parent.width` 指向 `Row`，而 `Row` 的 `width` 又依赖 `parent.width`（Column），Column 又在 `Flickable.contentItem` 中——解析链断裂，所有宽度坍缩为 0。

**解决方案**：去掉 ScrollView，用 `Column { anchors { left/right/top/bottom } }` 直接约束在主区域。表单内容在当前窗高下无溢出，不需要滚动。

### 3.2 组件通信选信号而非双向绑定

`GenderButton` 如果用 `selectedValue: root.gender` + `onClicked: selectedValue = value`，一旦点击就打断绑定。

**解决方案**：用 `signal clicked(int value)` + 父页面 `onClicked: function(v) { root.gender = v }`，单向数据流清晰。

## 四、实施方案

### 文件清单

```
src/ui/qml/RegisterPage.qml      ← Step 1 主页面
src/ui/qml/RegisterWindow.qml    ← 独立 ApplicationWindow (420×680)
src/ui/components/BodyDataCard.qml ← 三列并排身体数据卡片
src/ui/components/GenderButton.qml ← 性别二选一按钮
src/ui/components/GoalCard.qml   ← 饮食目标卡片
```

### 关键踩坑

| 现象 | 根因 | 修复 |
|------|------|------|
| 主窗口左上角文字堆叠 | 预创建的 4 个 Page 未设 `visible: false`，作为 ApplicationWindow 直接子元素全部渲染在 (0,0) | 加 `visible: false` |
| RegisterPage 嵌入 main.qml 时布局混乱 | ScrollView 内部 `parent.width` 解析链断裂 | 去掉 ScrollView，用 anchors 约束 |
| `Unexpected token ';'` | QML 不支持 `width: x; height: y` 单行分号分隔属性 | 拆成多行 |
| Type RegisterPage unavailable | 分号语法错误导致 QML 解析失败后的级联报错 | 同上 |
