# 601. 冰箱库存模块：聚合+JOIN+软删除

## 设计要点
1. **多批次聚合**：同一食材可能有多个采购批次（不同时间、不同来源），展示时应按 ingredient_id 汇总显示总数量
2. **JOIN 食材表**：inventory_batches 只存 ingredient_id，展示时需要 JOIN ingredients 获取名称和类别
3. **软删除 vs 真删除**：校准清空使用 `is_deleted=1` 而非 DELETE，保留审计轨迹

## 坑：SELECT ib.* + AS 别名在 QSqlRecord 的兼容性
- `SELECT ib.*, i.name AS ingredient_name FROM inventory_batches ib JOIN ingredients i` 
- 在部分 Qt/SQLite 版本中，`query.record().indexOf("ingredient_name")` 返回 -1
- **安全写法**：先 `record().indexOf()` 判断再 `query.value()`，或改用 `ingRepo_->getById()` 独立查询

## FIFO 核销
```cpp
// 按 expiry_date ASC 排序，从最早批开始扣
auto batches = getByFamilyAndIngredient(familyId, ingredientId);
for (const auto &b : batches) {
    double take = qMin(remaining, b.batch_quantity);
    deductBatch(b.id, take, ...);
    remaining -= take;
}
```

# 602. inventory_logs 表设计：审计轨迹

## 字段
| 字段 | 说明 |
|------|------|
| operation | deduct / add / undo / calibrate |
| quantity_change | 正=入库，负=消耗 |
| quantity_before / after | 快照 |
| reason | `cooking:<batchId>` 格式，用于 undo 追溯 |
| related_menu_id | 可空，关联 daily_menus.id |

## FK 陷阱
- `related_menu_id REFERENCES daily_menus(id)` — 但消耗时传入的是 menu_items.id
- **SQLite FK 对 NULL 不检查** → 直接传 NULL 即可避免

## 自动建表
```cpp
QSqlQuery ct(...);
ct.exec("CREATE TABLE IF NOT EXISTS inventory_logs (...)");
```
- 防御旧数据库没有该表的情况
- 注意：已有表的列约束不会更新

# 603. QML Popup 布局层级陷阱

## nested Popup 问题
在 Popup 的 contentItem 里再放 Popup 会导致：
1. `parent.width` 引用混乱（指向上层 Popup 的 contentItem 而非 Popup 本身）
2. 布局计算失效

**解法**：
```qml
Popup {
    padding: 16
    contentItem: Item {
        // 内容用独立的 Column+锚点，不依赖 parent
        Column {
            anchors.centerIn: parent
            ...
        }
    }
}
```

# 604. 冰箱感知采购算法

```
需购量 = Σ(菜谱食材量 × 份数倍率) − Σ(冰箱该食材存量)
```

- **PurchaseService::getTodayPurchaseList** 先查冰箱库存，再按食材聚合菜谱需求，相减
- 需购量 ≤ 0 → 不下发到采购清单
- 采购清单支持实际购买量手动调整（±50g 步进 + 一键足量）

# 605. 项目架构反思

## 当前痛点
1. **无测试**：10 Service / 50+ 方法全靠手工点，重构极易引入回归
2. **无输入校验**：QML TextInput 直传 C++，负数/0/空都能过
3. **无错误反馈**：C++ return false → QML 无 toast，用户感知不到失败
4. **数据库迁移弱**：只有 CREATE TABLE IF NOT EXISTS，加不了新列

## 改进方向
- 引入 Qt Test 框架做 Service 层单元测试
- 统一校验层：在 Service 每个 Q_INVOKABLE 入口做参数范围校验
- 统一错误提示：定义 `signal operationFailed(QString message)` → QML toast
- 引入 SQL 迁移工具或版本号 → `schema_version` 表 + 升级脚本
